# 船员航行仪表的双人验收

GitHub 的独立 Ubuntu 测试机启动一台 Forge 1.20.1 专服和两套中文 Minecraft 客户端。船长和工程师各自用独立的生存账号、游戏进程与 Xvfb 显示器连接。该场景在新生成的世界中预置舰桥、舱内熔炉、起航能量、工程师的一块原铁和一块煤。服务器为船长开启从主世界到 Galacticraft 原月球的巡航。

工程师用绑定的使用键，空主手点击实际舰桥方块。船长在自己的驾驶席先点接管，再恢复自动驾驶。工程师的同一扇船员仪表窗须先后显示自动巡航、人工驾驶、恢复巡航。每一帧核对船长、航线、指令来源、当前位置对应的进度箭头、速度、剩余航距和预留能量。服务端单程航费和航行保护额度分别记录。

工程师点「完成」回到甲板，再用使用键打开实际熔炉，把背包里的原铁和煤放进两个槽，等铁锭出现后取回。专服记录船员身份、两次主手方块交互、船长的控制变化、出炉事件，以及熔炉打开期间的航距变化。正常关服后从两份独立角色 NBT 和 `level.dat` 复核身份、铁锭、关闭作弊和空 OP 名单。

`crew-flight-display-运行编号-尝试次数` 产物包括三个航行状态和熔炉的原图、两侧输入和日志、专服记录、两份角色存档以及世界设置。安装 Pillow 后，可在仓库根对已下载的产物执行 `python -B qa/crew-display/replay_crew.py 原始产物.zip --sha256 产物摘要`。离线输入保护及仪表像素检查用 `python -B -m unittest discover -s qa/crew-display -v`。本场景观察的驾驶指令来自船长舰桥。电脑和 MCP 的独立验收见 `qa/bridge-controls`。
